# 分析协议

本协议是按问题取用的核对参考。完整深读按论文原文章节和论证走，跨章节的机制整理可以用主题标题。先给问题与总图，再展开关键证据，最后回到结论。局部解释可以直接从用户所在的图、公式、数据或指标开始。

## 来源边界

登记来源 ID、文件或 URL、版本、身份、已读范围和缺口。尽量给读者可以跳到对应段、图或代码行的入口。

| 标签 | 可用证据与定位 |
|---|---|
| [PAPER] | 原文或作者附录明确支持。给版本、正文或附录、PDF 页序及图/表/公式/段落位置。引用其他论文时标明身份。 |
| [CODE] | 已查的实现或配置。给仓库、提交或工作树状态、文件、行号与实际使用条件。 |
| [OBSERVED] | 实际读取到的样本、权重或运行结果。写对象、方法和观测范围。 |
| [INFERENCE] | 可从证据推出的结论。写明所用证据、运算、假设与边界。 |
| [EXAMPLE] | 教学输入、张量或算例。标为示意，保持形状和运算一致。 |
| [UNKNOWN] | 说明何处未公开或尚未核验、会影响哪一步、还需什么材料。 |

标签贴近所支持的说法。区分 PDF 页序与印刷页码。图片缺失或公式提取损坏时回查 PDF；仍不可读就注明。正文与表格、不同版本或当前代码不一致时并列。真实输入、归档计划、参考样本和模型输出可能共用案例编号，各自的形状、长度和证据需分别核对。

## 问题、总图与模块关系

- 说明论文解决什么，以及用户提供的输入、系统直接输出和人最终看到的效果。依方法章节和原图追到输出。存在数据准备、训练、推理或后处理时，明确它们在哪条路上。
- 解读原图时放大原图核对版本、图号、子图、图例、线型和端点。区分数据流、并行条件、上下层包含、关联、组件复用和示意。单凭线型、数据库图标或留白不足以断定格式或运算。
- 核心节点说明输入的类型、形状和来源，节点执行的操作，输出及其下游。复杂结构展开到论文已公开的操作；有源码授权时再单列实际实现。图上每个输出应有真实终点。

## 表示、操作与形状

- 沿关键路径讲清物理存储、运行时对象、字段、dtype、shape、轴、单位和有效长度。说明操作为何需要及对信息的影响。真实 schema 核对写入和读取两端。维度标明来自定义、配置、观测还是计算。
- 区分序列长度、容量、步长和标记槽。只解释实际发生的采样、分箱、取整、EOS、截断、补齐、拼接和 mask。区分留白、省略、不适用、缺失和明确的零值。
- 术语卡住时先用一个小例子说操作，再连接原图、公式和真实维度。对 Codebook 区分类别、整数编号、码本行、可学习向量、激活向量，给明确的查表/组合/量化方式。对分组数组写索引起点、端点开闭和每段列数。
- 需要贯穿实例时优先采用有来源的同一个输入；其余节点给简明 shape 示意。公开材料不足时可以给教学算例，并分段标明。作者动机注明出处，提出的替代解释标为推断。

| 节点或箭头 | 对象、类型与 shape | 操作或依赖 | 输出语义及下游 | 依据与未知 |
|---|---|---|---|---|

## 训练、推理与实验

- 分别交代训练的输入、条件、监督数据如何配对，以及推理时真正可用的资产。对相关公式给各变量含义、形状、单位与角色，说明损失比较哪两个量、mask 或归约在哪个轴、哪些参数接收更新。区分固定规则、预训练后保持参数的模块和参与本任务更新的模块。
- 沿推理路径追概率如何变选择、表示如何变输出，以及采样、阈值、约束和终止。用户要求核对数据泄漏时，追训练/测试划分、索引与预处理拟合范围，说明作者是否使用评测标注或 Human/oracle 条件。缺证据时给出核查边界。
- 沿“问题 → 改变 → 对照 → 结果 → 能支持的结论”核对实验。确认真实测试集、基线输入与条件、指标方向、候选与命中规则、重复和不确定性。需解释数值时用可复算的小例子。核对百分比、倍数和总量口径；经验最优的范围由分组和实验条件决定。

## 收束与交付核对

回到起点的问题、实际已证的贡献和局限，确认关键输入可以沿解释走到输出。复查数据轴、公式算例、论文与代码身份、训练/推理隔离、对照的标签和数值以及证据链接。自测题适合互动学习、复习或专门请求时加入，覆盖用户最容易读错的机制。完整报告按承诺的原文范围和实质覆盖验收；缺页、缺模型或未运行的事实要就地说明。
