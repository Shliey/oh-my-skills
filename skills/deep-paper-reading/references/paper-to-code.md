# 论文与源码对照（按需）

仅在用户明确要求源码领读、解释实际实现或比较论文与代码时使用。按用户选择的阅读模式收敛范围；普通论文分析不读取本参考。只读对照不等于获得运行、安装或修改代码的授权。

1. **先固定两侧版本。** 记录论文版本及公式/章节，代码仓库、提交或本地工作树状态、数据集和生效配置。明确默认配置与覆盖项；无法取得源码时保留纸面分析，并说明哪项对照无法完成。
2. **沿方法定位代码。** 先讲任务、输入输出和模块为什么存在，再用一个例子追踪数据准备、调用入口、核心运算和输出。引用实际函数和文件行号，必要时给最短相关片段。沿用作者和源码术语；函数名只是线索，以运算、字段、轴、切片、掩码和配置为准。
3. **并列结论。** 用“论文写了什么 → 当前代码实际计算什么 → 对这个例子的影响”解释一致或差异。分别使用原有论文证据标签、`[源码观察]`、`[运行观察]`（实际执行才用）和 `[教学示例]`。源码发现不改写论文结论；版本未核对时不要把差异归因为错误。区分可从源码推出的行为、测到的行为和仍未知的情况。
4. **限定运行结论。** 如用户明确要求运行且具备条件，给环境、数据、命令与观测结果；小样本或短程测试仅证明实际走过的路径，不证明论文指标或复现成功。没有外传授权的本地材料保持本地。

例如，若论文公式比较相邻帧差，而名为 `velocity_loss` 的实现只沿最后一轴切出位置通道做逐帧 L1，就画出两个轴，分别手算同一组两帧数据，并指出结果为什么不同。这里是教学情形，不是对任何项目的运行结论。
